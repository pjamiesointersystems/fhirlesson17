### fhir.resources 7.x Import Path Changes
Version 7.x reorganizes resource imports into sub-packages by FHIR version. The lesson uses FHIR R4, which in fhir.resources 7.x is the `R4B` (R4 Ballot) sub-package. [Inference based on fhir.resources 7.x package structure]

**Old (6.x):**
```python
from fhir.resources.patient import Patient
from fhir.resources.observation import Observation
from fhir.resources.bundle import Bundle
```

**New (7.x):**
```python
from fhir.resources.R4B.patient import Patient
from fhir.resources.R4B.observation import Observation
from fhir.resources.R4B.bundle import Bundle
```

Verify this structure in the smoke test. If the import fails or the sub-package is named differently (e.g., `R4` instead of `R4B`), document the actual structure discovered. [Inference]

### Pydantic v2 Migration Note
The existing codebase uses `parse_obj()` throughout (Pydantic v1 API). Version 2 replaces this with `model_validate()`. This story does NOT migrate the code — that happens in Story 1.3 (FHIR client refactor). This story only verifies that the dependencies install and import successfully. [Source: tech-spec.md#FR-008; tech-spec.md#FR-003]

## Testing

<!-- LOCKED. External dev tools must not edit Testing. -->

### Validation Strategy
This story's "testing" is installation validation — the smoke test IS the test.

**Test 1: Clean Install**
- Environment: Fresh Python 3.11+ venv in a temporary directory (not the project venv)
- Steps:
  1. Create venv: `python3.11 -m venv /tmp/lesson17-test-venv`
  2. Activate: `source /tmp/lesson17-test-venv/bin/activate`
  3. Install: `pip install -r FHIRAI/requirements.txt`
  4. Expected: No version conflict errors, all packages install successfully
- Success criteria: `pip install` exits with code 0

**Test 2: Import Smoke Test**
- Environment: The clean venv from Test 1
- Steps:
  1. Run the smoke test script created during implementation
  2. Expected: All imports succeed, script prints success message
- Success criteria: Script exits with code 0, no ImportError

**Test 3: R4B Sub-Package Verification**
- Environment: The clean venv from Test 1
- Steps:
  1. Start Python REPL
  2. `from fhir.resources.R4B.patient import Patient`
  3. `p = Patient.model_validate({"resourceType": "Patient", "id": "123"})`
  4. Expected: No ImportError, no AttributeError (model_validate exists)
- Success criteria: Patient object is created; Pydantic v2 API is available

**Edge Case: Version Conflict Detection**
- If pip reports a version conflict during install (e.g., two packages require incompatible versions of a shared dependency), this is a FAILURE. Document the conflict and resolve by adjusting version constraints or removing a package. [Inference]

**No Unit Tests Required**
This is a dependency manifest. There is no code logic to unit test. The validation is environmental (can it install?) and interface-level (can it import?). [Inference]
