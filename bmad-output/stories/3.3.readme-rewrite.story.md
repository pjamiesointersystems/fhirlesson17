### Purpose

The Readme.md is the primary entry point for students and instructors using Lesson 17. It must be a complete lesson guide: setup, concepts, exercises, and series context. This story rewrites the existing Readme (currently minimal) into a comprehensive document. [Source: tech-spec.md#FR-006]

### Structure (from tech-spec.md#FR-006)

Required sections in order:

1. **Lesson overview**: What this lesson teaches (foundational AI+FHIR) and what it does NOT teach (agentic AI, MCP, RAG). Students arrive with FHIR knowledge but no AI background.

2. **Series position**: Lesson 17 is the first in a four-part series. Explain how it connects to Parts One/Two (agentic AI) and RAG Lab. [Source: SPEC.md#series-context]

3. **Learning objectives**: Mapped to SPEC.md#capabilities:
   - Explain core LLM concepts (tokens, embeddings, context windows, temperature, prompts, hallucination) using healthcare analogies
   - Set up and interact with local LLM (Ollama/LM Studio) from Python
   - Transform FHIR patient bundle into LLM-ready input
   - Build a working patient summarization pipeline
   - Apply prompt engineering techniques (system roles, structured output, few-shot)
   - Articulate safety and governance principles for AI+healthcare

4. **Prerequisites**:
   - Completion of prior FHIR lessons (specify which lessons cover Patient, Observation, Bundle, FHIRPath)
   - Python 3.11+ installed with venv capability
   - Local InterSystems IRIS for Health FHIR R4 server running with Synthea data loaded
   - Basic command-line familiarity

   [Source: tech-spec.md#FR-006, tech-spec.md#assumptions]

5. **Environment setup** (detailed):
   - **Ollama installation**: macOS (`brew install ollama`), Windows (installer), Linux (script). Include links to Ollama docs.
   - **Model download**: `ollama pull llama3.2:3b` (or instructor's preferred model). Explain model size vs. capability trade-off briefly.
   - **Python venv**: `cd FHIRAI && python3 -m venv .venv && source .venv/bin/activate` (macOS/Linux) or `.venv\Scripts\activate` (Windows)
   - **Dependencies**: `pip install -r requirements.txt`
   - **Configuration**: Copy `.env.example` to `.env`, edit FHIR server URL/credentials and LLM model name. Explain each config variable.

   [Source: tech-spec.md#FR-006, tech-spec.md#FR-007]

6. **Phase 1 summary**: Brief overview of AI foundations slide topics (LLM architecture, tokens, context windows, embeddings, temperature, prompts, hallucination, local vs. cloud, model selection). Reference `slides/ai_foundations.md` for full content.

7. **Exercise walkthroughs**: For each of Exercises 1-4:
   - **What it teaches** (mapped to tech-spec FRs)
   - **Setup steps** (pre-flight checks, e.g., "ensure Ollama is running")
   - **How to run** (command-line invocation)
   - **Expected output** (what students should see if successful)
   - **Discussion prompts** (what to notice, what concepts the exercise demonstrates)

   Exercise details from tech-spec.md:
   - **Exercise 1** (FR-002): LLM connectivity and first chat. Tests Ollama setup, error handling.
   - **Exercise 2** (FR-003): FHIR bundle retrieval and size exploration. Demonstrates "too big for context window" problem.
   - **Exercise 3** (FR-004): Patient summarization CLI pipeline (NOT Textual TUI — see decision-log.md "Drop Textual TUI"). Core exercise: fetch → group → extract → LLM → print. [Source: decision-log.md 2026-10-08]
   - **Exercise 4** (FR-005): Prompt engineering comparison. 3+ prompt strategies, side-by-side output, observable differences.

8. **Phase 3 summary**: Reference safety/governance slides and series bridge content. Explain that these frame the rest of the series.

9. **Safety and governance discussion points**: Summarize key principles (hallucination, PHI/HIPAA, human-in-the-loop, golden rule, regulatory awareness). Reference `slides/safety_governance.md` for full content. [Source: tech-spec.md#FR-010]

10. **Further reading/resources**: Links to Ollama documentation, FHIR spec, relevant papers. Preview what's covered in Parts One/Two and RAG Lab.

- Ollama install: Homebrew (macOS), installer (Windows), script (Linux)
- Python venv activation: `source .venv/bin/activate` (macOS/Linux) vs. `.venv\Scripts\activate` (Windows)
- Path separators: note where commands differ

[Source: tech-spec.md#FR-006, tech-spec.md#non-functional-requirements]
