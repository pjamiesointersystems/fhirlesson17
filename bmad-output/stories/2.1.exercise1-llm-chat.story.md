## Story

**As a** healthcare informatics student with FHIR knowledge but no prior AI/ML background
**I want** a minimal script that connects to a local LLM and sends a healthcare-related prompt
**So that** I can verify my local LLM environment works and see my first LLM response before moving to FHIR integration.

## Dev Notes

<!-- LOCKED. External dev tools must not edit Dev Notes. -->

**Purpose:** This is the "hello world" exercise for local LLM interaction. Students run this first to confirm their environment (Ollama or LM Studio) is set up correctly before adding FHIR complexity in Exercise 2. The script demonstrates the most basic LLM workflow: send prompt → receive response.

**Requirements Covered:**
- FR-002: Exercise 1 — Local LLM setup and first chat [Source: tech-spec.md#FR-002]

**Implementation Guidance:**

1. **Primary LLM Provider: Ollama** [Source: tech-spec.md#FR-002]
   - Use the `ollama` Python package (>=0.4.0)
   - The config.py module (from Story 1.2) provides a `get_llm_client()` factory that returns an Ollama client when `LLM_PROVIDER=ollama` in .env
   - Connection: Ollama defaults to `http://localhost:11434` (no explicit URL configuration needed for Exercise 1)
   - Example call pattern (pseudocode):
     ```python
     client = config.get_llm_client()
     response = client.chat(model=config.LLM_MODEL, messages=[...])
     ```

2. **Secondary LLM Provider: LM Studio** [Source: tech-spec.md#FR-002]
   - Keep as a commented alternative to demonstrate provider abstraction
   - Use the `lmstudio` Python SDK (>=1.5.0)
   - The config.py factory returns an LM Studio client when `LLM_PROVIDER=lmstudio`
   - Comment block should show the same prompt/response flow with lmstudio SDK syntax

3. **Prompt Selection** [Source: tech-spec.md#FR-002]
   - Use a simple healthcare-related prompt to maintain thematic consistency with the lesson
   - Suggested: "Explain what an A1c test measures in simple terms" or similar clinical concept
   - Keep it non-PHI and general enough that any reasonable model can answer

4. **Error Handling** [Source: tech-spec.md#FR-002]
   - **Connection failure:** LLM service not running. Message should guide student to start Ollama/LM Studio.
   - **Model not loaded:** Requested model not found. Message should suggest `ollama pull {model_name}` for Ollama.
   - These are the two most common student setup issues; handling them explicitly reduces support burden.

5. **Configuration Integration** [Source: tech-spec.md#FR-007, FR-002]
   - Script imports from config.py (Story 1.2 deliverable)
   - Reads `config.LLM_MODEL` and `config.LLM_PROVIDER` or uses `config.get_llm_client()`
   - No hardcoded model names or provider strings in this script
   - If .env is missing, config.py provides defaults with a warning (handled by config module, not this script)

6. **Output Format** [Source: tech-spec.md#FR-002]
   - Simple terminal output: print the prompt, then print the response
   - No fancy formatting — this is a pedagogical "hello world", not a production app
   - Students should see:
     ```
     Prompt: Explain what an A1c test measures in simple terms
     Response: [LLM output here]
     ```

**Dependencies:**
- Story 1.2 (config.py with get_llm_client() factory) must be complete [Inference: config.py is the source of LLM_MODEL, LLM_PROVIDER, and client factory]
- Ollama installed locally with at least one model pulled (student setup, documented in Readme from Story 3.3) [Source: tech-spec.md#internal-dependencies]

**Edge Cases:**
- LLM service not running: graceful error with actionable message
- Model not loaded: graceful error with `ollama pull` suggestion
- Slow response (large model on weak hardware): not an error, but script should not timeout prematurely. Use a reasonable timeout (e.g., 60s) or none.
- Empty response from LLM: unlikely for a simple prompt, but handle by printing "No response received"

**Testing Strategy:**
- Manual verification: Run with Ollama running → should print response
- Manual verification: Run with Ollama stopped → should print connection error message
- Manual verification: Run with model not loaded → should print model-not-found message
- Code inspection: Verify no hardcoded model names or provider strings
