## Testing

<!-- LOCKED. External dev tools must not edit Testing. -->

### Strategy

Cleanup testing is primarily verification. The dev tool should verify:

1. **Pre-cleanup file inventory**: Before moving or deleting any file, list all `.py` files in `FHIRAI/` (excluding `.venv/` and `100Set/`). This is the baseline inventory for comparison.

2. **Dependency check**: Verify that story 1.3 is complete. Check for the existence of `FHIRAI/fhir_client.py`. If it does not exist, HALT cleanup and note the dependency in testing results.

3. **Move/delete operations**: For each file in the disposition table:
   - Verify the file exists before attempting to move/delete
   - After moving to `archive/`, verify it no longer exists in `FHIRAI/` and does exist in `FHIRAI/archive/`
   - After deleting, verify it no longer exists anywhere in the repo (not in `FHIRAI/`, not in `archive/`)

4. **Archive README creation**: Verify `FHIRAI/archive/README.md` exists and contains:
   - List of archived files
   - Archive date and story ID
   - Explanation of why files were archived

5. **Post-cleanup file inventory**: List all `.py` files in `FHIRAI/` after cleanup. Compare to the expected active file list (exercise1-4, fhir_client, config). Flag any unexpected files.

6. **Import smoke test**: After cleanup, verify that the active exercise scripts can still import shared modules (config, fhir_client). Run:
   ```bash
   python -c "from fhir_client import get_everything_for_patient; from config import FHIR_BASE_URL"
   ```
   If imports fail, cleanup may have broken dependencies.

7. **Cross-story reference check**: Search all story files (`bmad-output/stories/*.story.md`) for references to moved/deleted files. If any story references a file that was cleaned up, flag it as a potential conflict.

No test code, no coverage metrics. This is file system operation verification.
