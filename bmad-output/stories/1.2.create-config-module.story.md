## Story

**As a** course maintainer
**I want** a central configuration module that loads settings from `.env`
**so that** no hardcoded URLs, credentials, or model names appear in exercise scripts and students can configure their environment without editing code

### config.py Implementation Pattern
Use a flat module with module-level constants loaded at import time. This is simpler than a class-based config or a factory pattern, appropriate for educational code. [Inference]

```python
# config.py
"""
Configuration loader for Lesson 17 (Using LLMs with FHIR).

Loads settings from .env file in the FHIRAI/ directory.
If .env is missing, uses sensible defaults for the course environment.
Students should copy .env.example to .env and customize.
"""
import os
import sys
from pathlib import Path
from dotenv import load_dotenv

# Load .env from the same directory as this file
env_path = Path(__file__).parent / ".env"
load_dotenv(dotenv_path=env_path)

# Warn if .env is missing
if not env_path.exists():
    print(
        "Warning: .env file not found. Using defaults. "
        "Copy .env.example to .env and customize for your environment.",
        file=sys.stderr
    )

# FHIR Server Configuration
FHIR_BASE_URL = os.getenv(
    "FHIR_BASE_URL",
    "http://127.0.0.1:8080/csp/healthshare/demo/fhir/r4"
)
FHIR_USERNAME = os.getenv("FHIR_USERNAME", "_System")
FHIR_PASSWORD = os.getenv("FHIR_PASSWORD", "ISCDEMO")

# LLM Configuration
LLM_MODEL = os.getenv("LLM_MODEL", "llama3.2:3b")
LLM_PROVIDER = os.getenv("LLM_PROVIDER", "ollama")  # "ollama" or "lmstudio"
```

This pattern is explicit, easy for students to read, and avoids over-engineering. [Inference]

### .env.example Structure
The example file should be a template students copy and fill in. Use comments to explain each key. [Inference]

```bash
# .env.example
# Configuration template for Lesson 17 (Using LLMs with FHIR)
# Copy this file to .env and customize the values for your environment.

# FHIR Server (InterSystems IRIS for Health)
# Base URL for the FHIR R4 endpoint (from prior lessons)
FHIR_BASE_URL=http://127.0.0.1:8080/csp/healthshare/demo/fhir/r4

# FHIR Server Authentication
FHIR_USERNAME=_System
FHIR_PASSWORD=YOUR_PASSWORD_HERE

# Local LLM Configuration
# Model name (for Ollama: "llama3.2:3b" or similar; for LM Studio: model identifier from the UI)
LLM_MODEL=llama3.2:3b

# LLM Provider ("ollama" or "lmstudio")
LLM_PROVIDER=ollama
```

The `YOUR_PASSWORD_HERE` placeholder forces students to think about the value rather than blindly copying. The default password from prior lessons is `ISCDEMO`, but using a placeholder reinforces security hygiene. [Inference]

## Testing

<!-- LOCKED. External dev tools must not edit Testing. -->

### Validation Strategy
This story's testing is module-load validation and default-value verification.

**Test 1: Module Import Without .env**
- Environment: Temporarily rename or move `.env` (if it exists) so the module cannot find it
- Steps:
  1. Start Python REPL
  2. `import config`
  3. Expected: Warning printed to stderr, no crash
  4. `print(config.FHIR_BASE_URL)` — should print the default URL
  5. `print(config.LLM_PROVIDER)` — should print `"ollama"`
- Success criteria: No ImportError, no crash, defaults are applied, warning is printed

**Test 2: Module Import With .env**
- Environment: Create a `.env` file with custom values
- Steps:
  1. Write `.env` with `FHIR_BASE_URL=http://custom.example.com/fhir/r4`
  2. Write `LLM_PROVIDER=lmstudio`
  3. Start Python REPL
  4. `import config`
  5. Expected: No warning, custom values loaded
  6. `print(config.FHIR_BASE_URL)` — should print `"http://custom.example.com/fhir/r4"`
  7. `print(config.LLM_PROVIDER)` — should print `"lmstudio"`
- Success criteria: Custom values override defaults, no warning printed

**Test 3: .gitignore Contains .env**
- Steps:
  1. Read `FHIRAI/.gitignore`
  2. Expected: `.env` appears exactly once (no duplicates)
- Success criteria: `.env` is listed

**Test 4: .env.example Is Valid**
- Steps:
  1. Copy `.env.example` to `.env`
  2. Replace `YOUR_PASSWORD_HERE` with `ISCDEMO`
  3. Run Test 2 (module import with .env)
  4. Expected: Config loads successfully
- Success criteria: `.env.example` structure is correct and usable

**Edge Case: Malformed .env**
- If `.env` exists but has syntax errors (e.g., missing `=`), `load_dotenv()` silently ignores the malformed line and falls back to defaults or `os.getenv()` behavior. This is acceptable — students will notice when their custom values are not applied and will debug the syntax. No special handling required. [Inference]

**No Unit Tests Required**
This is a configuration loader. There is no business logic to unit test. Validation is environmental: does it load? Does it warn? Do defaults work? [Inference]
