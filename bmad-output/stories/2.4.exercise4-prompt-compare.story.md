## Story

**As a** healthcare informatics student learning prompt engineering
**I want** a script that runs the same FHIR patient data through multiple prompting strategies and shows side-by-side results
**So that** I see concretely how different prompts produce different LLM outputs and learn prompt engineering as a practical skill, not just theory.

---

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. Script demonstrates at least 3 distinct prompting strategies: (a) minimal/baseline prompt, (b) structured system prompt with role and format specification, (c) few-shot prompt with example input/output pair.
2. Script runs all strategies on the same patient data (same FHIR bundle, same extracted features from Exercise 3's approach) to ensure valid comparison.
3. Script displays results in a clear, side-by-side or sequential format with labeled sections (Strategy 1, Strategy 2, Strategy 3) and inline comments explaining why each strategy produces different results.
4. Script includes at least one temperature comparison (e.g., temperature 0.1 vs 0.7 vs 1.0 on the same prompt) demonstrating the effect of sampling parameters on output variability.
5. Script output is pedagogically structured so students can easily modify prompts, re-run, and experiment — prompts are defined as clearly labeled string constants at the top of the file, not buried in function calls.

## Dev Notes

<!-- LOCKED. External dev tools must not edit Dev Notes. -->

**Purpose:** Exercise 4 teaches prompt engineering as a practical, observable skill. Students see the same FHIR patient data produce radically different summaries based on prompt structure, system role, examples, and sampling parameters. This is the "aha moment" where prompt engineering stops being abstract advice ("be clear and specific") and becomes concrete technique. The side-by-side comparison and inline explanatory comments make the lesson stick.

**Requirements Covered:**
- FR-005: Exercise 4 — Prompt engineering comparison [Source: tech-spec.md#FR-005]

**Implementation Guidance:**

1. **Reuse Exercise 3's Data Preparation** [Source: tech-spec.md#FR-005]
   - Fetch `Patient/$everything` via `fhir_client.get_everything_for_patient(patient_id)`
   - Group resources by type (same logic as Exercise 3)
   - Extract clinical features (same logic as Exercise 3)
   - Store extracted features as a string variable: `extracted_features_text`
   - This ensures ALL prompt strategies work on identical data, making comparison valid
   - Consider factoring the grouping/extraction logic into a shared helper function if it's verbose, but inline repetition is acceptable for educational clarity

2. **Prompt Strategy 1: Minimal/Baseline** [Source: tech-spec.md#FR-005]
   - This is the "naive" approach: minimal guidance to the LLM
   - System prompt: none, or generic "You are a helpful assistant"
   - User prompt: "Summarize this patient data:" + extracted_features_text
   - Expected output: unstructured paragraph or bullet points, no consistent format
   - Teaching point: shows what happens without explicit instructions

3. **Prompt Strategy 2: Structured System Prompt** [Source: tech-spec.md#FR-005]
   - This is the "best practice" approach: clear role, output format, safety instruction
   - System prompt:
     - Role: "You are a clinical AI assistant reviewing patient data."
     - Format: "Summarize into sections: Demographics, Active Conditions, Medications, Recent Encounters, Recent Observations, Allergies, Notable Findings."
     - Safety: "Do not invent information not present in the data."
   - User prompt: extracted_features_text (no preamble needed, system prompt sets context)
   - Expected output: structured summary with section headers matching the request
   - Teaching point: shows how explicit instructions shape output format

4. **Prompt Strategy 3: Few-Shot Prompt** [Source: tech-spec.md#FR-005]
   - This demonstrates learning from examples
   - System prompt: "You are a clinical AI assistant. Here is an example summarization:"
   - Include a brief example:
     ```
     Input: Patient: Jane Doe, female, DOB 1985-06-15. Conditions: Hypertension (active). Medications: Lisinopril 10mg daily.
     Output:
     Demographics: Jane Doe, 38F
     Active Conditions: Hypertension
     Medications: Lisinopril 10mg daily
     ```
   - User prompt: "Now summarize this patient:" + extracted_features_text
   - Expected output: mimics the example format and style
   - Teaching point: shows how examples guide LLM behavior without explicit format instructions

5. **Temperature Comparison** [Source: tech-spec.md#FR-005]
   - Run Strategy 2 (structured prompt) three times with different temperature values:
     - **Temperature 0.1:** Nearly deterministic. LLM picks highest-probability tokens consistently. Output is focused and stable across runs.
     - **Temperature 0.7:** Balanced. Default for most tasks. Some creativity, reasonable consistency.
     - **Temperature 1.0:** Creative. More sampling variability. Output may vary significantly across runs, sometimes introduces unexpected phrasings.
   - Print all three outputs side-by-side or sequentially with clear labels
   - Teaching point: temperature controls the creativity/determinism tradeoff. Students see it concretely.
   - **Note:** Temperature effect is most visible on longer outputs. If summaries are short, differences may be subtle. Consider using a richer patient (more resources) or note in comments that effect is more pronounced with longer outputs.

6. **Output Display Format** [Source: tech-spec.md#FR-005]
   - Clear section headers: "=== Strategy X: [Name] ==="
   - Print LLM output immediately after header
   - Print inline comment explaining what to notice (as shown in Tasks)
   - Consider adding a blank line between strategies for readability
   - Example structure:
     ```
     === Strategy 1: Minimal Prompt (Baseline) ===
     [LLM output here]
     # Notice: baseline prompt often produces unstructured wall of text

     === Strategy 2: Structured System Prompt ===
     [LLM output here]
     # Notice: structured prompt produces sections matching the requested format
     ```

7. **Prompts as Editable Constants** [Source: tech-spec.md#FR-005]
   - Define all prompts as module-level string constants at the top of the file
   - Clear naming: `PROMPT_MINIMAL_SYSTEM`, `PROMPT_STRUCTURED_SYSTEM`, etc.
   - Include comments inviting students to edit: "# Try modifying this prompt to see how output changes"
   - This makes experimentation easy — students don't need to dig through function calls to find prompt strings

8. **Pedagogical Notes in Code** [Source: tech-spec.md#FR-005]
   - Add inline comments explaining WHY each strategy works differently [Source: tech-spec.md#FR-005 - "discussion prompts in comments"]
   - Example comment after Strategy 2 output: "# Structured prompts work because LLMs are trained to follow instructions. Clear format specification = predictable output structure."
   - These comments turn the script into a teaching document, not just a demo

9. **Optional: Save Outputs to Files** [Inference]
   - Consider saving each strategy's output to a file (`strategy1_output.txt`, etc.) so students can review side-by-side in a text editor
   - Useful if terminal output scrolls off screen
   - Not required, but pedagogically helpful

10. **Comparison Validity** [Source: tech-spec.md#FR-005]
    - All strategies MUST use the same `extracted_features_text` input
    - Patient ID should be the same across all runs (default "2" or configurable)
    - Temperature should be the same (0.7) for Strategies 1-3 comparison, only varying for the temperature comparison section
    - This ensures differences in output are due to prompt design, not data differences

**Dependencies:**
- Story 1.2 (config.py) — for `get_llm_client()` and LLM model config
- Story 1.3 (fhir_client.py) — for `get_everything_for_patient()`
- Story 2.3 (exercise3-summarizer-cli) — reuses the same data grouping/extraction pattern (pedagogical and pattern dependency)

**Edge Cases:**
- LLM timeout: catch and print error, but continue to next strategy (don't abort entire comparison)
- Temperature not supported by model: some local models ignore temperature parameter. Note in comments that effectiveness varies by model.
- Very short patient data: prompt differences may be less visible with minimal data. Script works, but teaching point is weaker. Recommend using patient with substantial data (multiple Conditions, Observations, Medications).

**Testing Strategy:**
- Manual verification: Run with patient "2" → should print outputs for all 3 strategies + temperature comparison
- Manual verification: Compare Strategy 1 vs Strategy 2 outputs → should see structural differences (unstructured vs. sectioned)
- Manual verification: Run temperature comparison → temp 0.1 should be consistent across runs, temp 1.0 should show variability if run multiple times
- Code inspection: Verify prompts are defined as constants at module level
- Code inspection: Verify inline explanatory comments are present after each output section

**Performance Note:**
- Script makes 6 LLM calls (3 strategies + 3 temperature variants). Total runtime may be 1-3 minutes on slow hardware. Print progress messages ("Running Strategy 1...", "Running Strategy 2...") so students know script is working.
